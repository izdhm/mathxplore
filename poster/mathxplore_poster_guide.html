04Copy, section by section

Problem, idea and the learning loop

01

The problem

left card · rose accent
Write this

Maths and code, taught apart

  • Two subjects, no bridge. Loops learnt on arbitrary examples; graphs never linked to code.
  • Answers without understanding. A calculator answers only what you already knew how to ask.
  • Errors that teach nothing. SyntaxError: invalid syntax is a dead end for a beginner.
If you want a fourth point

Needs the internet. Many learning tools depend on accounts, downloads and a fast connection.

02

Our idea

right card · green accent
Write this

Every Python concept arrives because a piece of mathematics needs it — and every picture on screen is also a program.

Diagram of three boxes joined by ⇄ arrows:
MATHEMATICS y = ax² + bx + c  ⇄  PICTURE (a parabola with its previous position dashed)  ⇄  PYTHON y = a*x**2 + b*x + c

Change any one and the other two follow — a slider rewrites the code, and the code redraws the graph.

Objectives — if your rubric asks for them
  1. To connect mathematical concepts and Python programming in one learning loop.
  2. To build understanding through prediction, manipulation and visualisation.
  3. To turn programming errors into mathematics-aware lessons for beginners.
  4. To provide a safe platform that runs in any modern browser, offline, with no account.
·

The learning loop

full-width band
Write this

One learning loop, lit up on every working screen — so a student always sees where they are, and that there is a next step.

Nine stages, each with a small tag underneath: LEARN 6-level pathway → EXPLORE 5 modules → PREDICT What If? → CHANGE live sliders → VISUALISE 2D · 3D → CODE CodeLab → TEST challenges → UNDERSTAND error lessons → CREATE sandbox · shapes

Icons: use the app's own line icons (book, eye, lightbulb, sliders, chart, code brackets, target, tick, flask). In Canva, the "line icons" set is close enough. Colour each stage by domain: violet, cyan, amber, violet, cyan, green, amber, green, violet.

04Copy, section by section

Abstract, in English and Bahasa Melayu

Not on the poster itself, but often requested for the abstract book, the registration form or a small panel beside the poster.

Abstract · 125 words

MathXplore is a browser-based interactive mathematics laboratory that teaches mathematics and Python programming together. Students see a function, change it with sliders, predict the outcome before it is revealed, and write the Python code that draws it. The platform provides five exploration modules (linear, quadratic and trigonometric functions, 3D surfaces and geometry), twelve predict-then-reveal "What If?" scenarios, a six-level Python × Mathematics pathway and twelve challenges graded by executing the student's code. A purpose-built Python engine, written in TypeScript, turns programming errors into plain-language lessons linked to mathematical notation, and runs safely inside the browser with no internet connection, installation or account. Built-in anonymous learning records prepare the platform for classroom evaluation through pre- and post-testing.

Abstrak · Bahasa Melayu (have a native speaker check it)

MathXplore ialah makmal matematik interaktif berasaskan pelayar web yang mengajar matematik dan pengaturcaraan Python secara bersepadu. Pelajar melihat sesuatu fungsi, mengubahnya menggunakan peluncur, meramal hasilnya sebelum didedahkan, dan menulis kod Python yang melukisnya. Platform ini menyediakan lima modul penerokaan (fungsi linear, kuadratik dan trigonometri, permukaan 3D serta geometri), dua belas senario ramal-dan-lihat "What If?", laluan Python × Matematik enam tahap dan dua belas cabaran yang dinilai dengan melaksanakan kod pelajar. Enjin Python yang dibina khas dalam TypeScript menukar ralat pengaturcaraan kepada pelajaran dalam bahasa mudah yang dikaitkan dengan tatatanda matematik, dan berjalan dengan selamat dalam pelayar tanpa sambungan internet, pemasangan atau akaun. Rekod pembelajaran tanpa nama yang terbina dalam menyediakan platform ini untuk penilaian bilik darjah melalui ujian pra dan pasca.

Don't claim these.
  • Any learning gain ("improves scores by X %"). It hasn't been measured, and the app itself says so. Say "evidence-ready" and describe the planned pilot.
  • "The first" or "the only". Unverifiable, and a judge who knows one counter-example will discount the rest. Use "combines, in one tool…".
  • Class rosters, activity authoring or report generation as working features. They are designed, not built; label them roadmap.
  • "Full Python". It is a teaching subset: no classes, dictionaries, comprehensions or exceptions, by design.
  • Curriculum alignment or market-size figures without a source. If you add them (e.g. KSSM topics, number of secondary students), cite the official document.
Honesty helps here. Academic judges respond well to "we haven't measured it yet — here is exactly how we will" — especially when the measuring apparatus is already built and you can show the export at the booth.
07At the booth

60-second pitch, demo route, likely questions

60-second pitch

"Mathematics and programming are hard partly because they're taught apart. MathXplore puts them in one lab. [point at the loop] A student sees a function, changes it with a slider, predicts what will happen before we show them, and then writes the Python that draws it. [hand over the laptop] Try it — what happens to this parabola if a goes from 1 to −1? … Now the same curve as code. If I make a typical beginner's mistake — 2x instead of 2*x — the lab doesn't just say 'syntax error'; it explains the maths reason. It runs completely offline, needs no account, and is checked by 182 automated tests. Next, we want to pilot it in a school with a pre- and post-test — the logging for that is already built in."

Demo route (2–3 minutes, from the README)

  1. Landing — rotate the live surface.
  2. Explore → Quadratic — move a; vertex, roots, axis and discriminant update.
  3. What If? — ask the judge to predict a: 1 → −1. They must commit before the reveal.
  4. Open in CodeLab — change a coefficient, Run; then type y = 2x + 3 for the error lesson.
  5. 3D Surfaces → Saddle — rotate it; show the cross-sections.
  6. Geometry → Polygon — drag n; the area closes in on the circle's.
  7. Challenges → Hit the target points — hand over the keyboard.
  8. Progress — the learning record and CSV export.

Likely questions

How is this different from Desmos or GeoGebra?They're excellent for seeing maths. MathXplore adds Python tied to the same maths, predict-then-reveal, errors explained in maths terms and grading by running code — all offline.
Why write your own Python engine instead of Pyodide?Three reasons: Pyodide needs a multi-megabyte download and the network; its raw errors teach nothing, while owning the parser means owning the message; and safety is structural — student code can reach only what we register.
Does it actually improve learning?Not measured yet, and we don't claim it. The event log, CSV/JSON export and anonymous participant codes are built for a pre/post-test pilot.
What about student data?Nothing leaves the browser. No accounts; a random participant code with no personal data; export only when the student chooses.
How would it make money?Free for students; school licences for the educator features; offline deployment kits and teacher training. Hosting is static files, so each extra student costs almost nothing.
What are the limitations?A deliberate Python subset (no classes or dictionaries); a simple mastery model; rosters and authoring still on the roadmap; 3D needs WebGL (2D always works).
How do you know it works?182 automated checks: Python behaviour against CPython, every grader against its reference solution, every page rendering, and a full app mount with no errors.
08Checklists

Before printing, and on the day

Before you send it to print

  • Size, orientation and logo rules confirmed with the secretariat
  • All amber placeholders replaced: logos, category, entry ID, team, supervisor, faculty, QR, email
  • Names spelt exactly as registered
  • QR code tested with two phones, from 1 m away
  • No text closer than 20 mm to the edge
  • Numbers re-checked if the app changed (section 06)
  • Proof-read out loud by someone who didn't write it
  • A3 test print checked for colour, then A0 on matte or satin paper
  • PDF opened once on another computer to confirm the fonts

To edit the ready-made poster

  1. Open poster/mathxplore_poster.html in a text editor (VS Code, Notepad++).
  2. Search class="fill" and replace each placeholder's text.
  3. For logos, replace each <div class="logo-slot">…</div> with <div class="logo-slot"><img src="assets/ums.png"></div>; for the QR, do the same inside qr-slot.
  4. Open the file in Chrome (be online so the fonts load) → Ctrl+P → Save as PDF → More settings: Margins None, Background graphics on → Save. The A0 size is picked up automatically.

On judging day (13 October)

  • Laptop with the app already running offline (npm run preview) — don't rely on venue wifi
  • A second copy of dist/ on a USB stick, plus a second browser
  • Charger and extension lead
  • Browser zoomed so the demo reads from 1.5 m; dark theme on
  • Progress page reset, or seeded with a clean demo record
  • What If? scenario 1 on the Quadratic page ready to go
  • The 60-second pitch rehearsed; each team member knows one part of the demo
  • Printed abstract (EN/BM) and a few A5 flyers with the QR
  • Answers to the "likely questions" divided between team members
Remember the blank-page trap. Double-clicking dist/index.html shows an empty dark page — browsers block module scripts on file://. Always serve it: npm run preview, or python -m http.server inside dist/.
